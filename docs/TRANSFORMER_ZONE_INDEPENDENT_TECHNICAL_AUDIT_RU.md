## 2. Блокирующие дефекты интеграции M1

### 2.1. GasCalc не входит в состав AutoCAD DLL

В AGPT.csproj установлено EnableDefaultCompileItems=false и перечислено пять файлов проекта. src/Calc/GasCalc.cs в Compile list отсутствует. Следовательно:
- отдельный GasCalc.Tests проект может успешно компилировать и тестировать GasCalc.cs;
- это не доказывает, что AGPT.dll содержит новую реализацию;
- текущий AGPT_CALC не может использовать GasCalc без изменения проекта и интеграционного слоя.

Это подтверждённое блокирующее расхождение, а не предположение.

### 2.2. Действующая команда AGPT_CALC использует старый расчёт

В src/AGPT_Stage3_Blocks_Full.cs команда AGPT_CALC вызывает MassCalc.Compute(z), затем MassCalc.SuggestVol(z.Mg).

Старый MassCalc:
- вычисляет Mp через Math.Log(100/(100-Cn));
- принимает Vtr=0.002 м³ по умолчанию;
- оценивает массу остатка через rho1 и фиксированный множитель 2.5;
- применяет старый набор модулей Flamex 40/60/80/100/120;
- при превышении вместимости каталога возвращает 120, а не состояние «требуется инженерное решение».

Последний пункт особенно опасен: значение 120 возвращается даже если требуемая масса выше максимальной заправки каталога. Это противоречит D4 в REQUIREMENTS.md, где прямо запрещён молчаливый выбор модуля и требуется показать варианты и ждать выбора инженера.

### 2.3. Вторая старая реализация расчёта остаётся активной в генераторе альбома

В src/AGPT_Plugin_Drawings.cs имеется отдельный Calc.Mass. Он:
- использует ln(100/(100-Cn));
- задаёт K3=1.0 как упрощённый коэффициент;
- подменяет невалидные исходные значения значениями по умолчанию;
- использует оценку плотности жидкой фазы 1400 кг/м³ и смешивает её с альтернативной оценкой Mтр;
- затем вызывается из Collect.FromModel и CalcSheet.

Таким образом, подключение GasCalc только к команде AGPT_CALC не завершит M1. Нужно устранить обе старые расчётные точки и провести единую цепочку данных: модель помещения → RoomInput → GasCalc → результат/предупреждения → модульный выбор инженера → листы/спецификация.

### 2.4. Два несовместимых каталога оборудования

Stage3 ModuleData.Cat содержит Flamex с заправками 20/30/40/50/60 кг для типоразмеров 40/60/80/100/120. Новый GasCalc.DefaultCatalog содержит Proffex 66-40-32 (28/42 кг), 66-50-32 (50 кг), 66-180-50 (184/192 кг).

Это не взаимозаменяемые модели. Каталоги должны быть вынесены в единый versioned EquipmentCatalog, содержащий изготовителя, точную маркировку, тип ГОТВ, паспортную заправку, остаток Mб, сосуд, давление, сертификаты, совместимые насадки и версию документа. Подмена одного каталога другим без документа производителя запрещена.

## 3. Проблемы модели исходных данных и генерации

### 3.1. Тихая подстановка демо-помещений нарушает E2

В Collect.FromModel, если после обхода ModelSpace не найдено ни одной реальной зоны, создаются четыре помещения детского сада с фиксированными объёмами и параметрами. REQUIREMENTS.md, E2, требует обратного поведения: предложить ввод зон вручную и остановиться; тихой подстановки демо-данных быть не должно.

До исправления E2 любой альбом, созданный при отсутствии реальной зоны, может быть ошибочно принят за результат реального объекта. Демо-режим следует оставить только в отдельной явно выбранной команде/режиме, маркировать каждый лист как DEMO и исключить его из рабочей спецификации.

### 3.2. Недостаточная полнота входов AGPT_ZONE

Текущий AGPT_ZONE сохраняет площадь/объём, высоту, суммарную площадь негерметичности, концентрацию, плотность ГОТВ и имя. Новая GasCalc требует также:
- FireKind / вид горючего;
- OpeningsPosition (проёмы сверху/снизу/оба);
- минимальную температуру;
- проектную высоту площадки и выбранное правило K3 между табличными строками;
- объём распределительного трубопровода;
- остаточное абсолютное давление после гидравлического расчёта;
- выбранный инженером набор модулей, если одного не хватает.

Эти данные должны вводиться/извлекаться из модели явно. Нельзя незаметно подставлять их из старого эталона или использовать коэффициенты как ручные overrides — это противоречит C8.

### 3.3. GasCalc ещё не является полностью подтверждённым расчётным ядром

Новый GasCalc лучше отделён от AutoCAD и использует для сжиженного ГОТВ отдельную формулу Г.3. Это правильная архитектурная основа, но до включения в проект остаются вопросы:
- EstimateRhoResidual использует оценку идеального газа с ограничением по VaporDensityCap; комментарий в коде сам требует проверки по паспорту.
- Mб остатка модулей в DefaultCatalog равен 0; сам код добавляет предупреждение. Пока нет паспорта и эксплуатационных данных, остаток нельзя считать подтверждённым.
- K3Mode LowerRow / Interpolate остаётся открытым проектным решением; REQUIREMENTS.md фиксирует вопрос для высоты Астаны 347 м.
- Необходима валидация диапазонов и физического смысла входов до вычисления, чтобы нулевые/отрицательные температура, объём, давление, высота и другие параметры не порождали NaN/Infinity или скрытые fallback значения.
- C# golden tests должны проверять не только арифметику, но и предупреждения/блокировки, инженерный выбор, неподтверждённые паспортные поля, граничные значения и единицы.

Тестовый проект GasCalc.Tests ссылается непосредственно на src/Calc/GasCalc.cs и компилирует его отдельно. Это полезный unit test, но не сборочный тест AGPT.dll и не доказательство вызова GasCalc из AutoCAD команды.

## 4. Гидравлика и насадки: текущие параметры нельзя считать проектными

В src/AGPT_Stage4_Hydro_Axo_v2.cs зафиксированы, в частности:
- Lambda = 0.02;
- RhoMix = 200 кг/м³;
- TNorm = 10 с;
- PModule = 25 бар;
- PMinNoz = 5 бар;
- RhoLiquid = 1400 кг/м³;
- WaveSpeed = 1000 м/с;
- PAllowPipe = 60 бар;
- оценочные PSat значения для HFC-227ea, HFC-125, FK-5-1-12.

Сам файл помечает некоторые из этих значений как типовые/оценочные. По текущему source snapshot не подтверждено, что они происходят из паспорта конкретного модуля, насадка, ГОТВ, труб или методики изготовителя. Они не должны использоваться как производственная гидравлика трансформаторной зоны.

PIPING_RULES.md прямо указывает, что:
- площадь/радиус действия насадка 360° отсутствует в нормативном разделе и должна браться из паспорта производителя;
- методика гидравлики HFC-227ea (давление перед насадком, время выпуска 95%, подбор диаметров) должна подтверждаться изготовителем/программой производителя;
- сортамент требует материал, фитинги, реальные внутренние диаметры и шаг креплений;
- препятствия в подоснове текущим эскизным алгоритмом не учитываются.

Следовательно, автоматическая генерация насадков и трассы может быть только геометрической черновой компоновкой до получения паспортных данных, и не может называться проверенной системой пожаротушения.

## 5. Трансформаторная зона: что можно и чего нельзя заключить сейчас

### Подтверждено

- В открытом чате Grok отображаются имена трёх файлов: ОПС_Дет_сад_ТП_с_модулями_в_зоне_трансформаторов.pdf, ОПС_Дет_сад_ТП_доработка_модули_пожаротушения.pdf и ОПС Дет сад - проект ТП после замечаний экспертизы.pdf.
- В открытом чате Claude последняя видимая часть заканчивается прерванным ответом «Подбор типа модулей для трансформерной камеры».
- Задача владельца отражена в bridge/INBOX.md: дооснастить зону трансформаторов модулями пожаротушения на основании приложенного PDF.
- В текущем доступном snapshot репозитория нет завершённого расчёта и подтверждённой схемы для этой зоны.

### Не подтверждено

Не подтверждены и не должны угадываться:
- количество, тип, мощность и конструкция трансформаторов;
- маслонаполненное или сухое исполнение, тип и масса масла;
- фактическая геометрия камер/перегородок/проёмов и смежные объёмы;
- высота, подвесной потолок, фальшпол и препятствия;
- действующие средства пожаротушения и пожарной сигнализации;
- возможность общего объёма тушения или необходимость раздельных зон;
- тип, марка, заправка и число модулей;
- число, расположение и ориентация насадков;
- диаметры и трасса распределительного трубопровода;
- время выпуска, остаточное давление и гидравлическая пригодность системы.

### Обязательные входные документы

1. Полный исходный PDF проекта ТП и PDF после замечаний экспертизы, с номером редакции и читаемыми листами.
2. Рабочий DWG (если план предполагается размещать непосредственно в нём) с единицами и подосновой.
3. Паспорт/сертификат выбранной серии модулей и ГОТВ, инструкция по монтажу/обслуживанию и данные по остаточной массе.
4. Паспорт 360° насадков и таблицы пропускной способности/параметров для требуемой ориентации и высоты.
5. Методика гидравлического расчёта изготовителя для конкретной пары «модуль + ГОТВ + насадок», включая допуски и критерии приемки.
6. Технические характеристики трансформаторов и подтверждение типа пожарной нагрузки от проектировщика/владельца объекта.
7. Конструктивные данные помещений и проёмов: геометрия, высоты, постоянные отверстия, вентиляция, пол/потолок и соседние объёмы.
8. Актуальная нормативная база РК и проектные требования, применимые к конкретному объекту; спорные пункты фиксируются с точной ссылкой и согласованием ответственного инженера.

До получения этих материалов выбор количества модулей и насадков, расчёт массы и гидравлика имеют статус BLOCKED.

## 6. Рекомендуемый план M1–M5

### M1 — единое расчётное ядро

- Включить GasCalc.cs в AGPT.csproj, затем убрать дублирующие legacy calls.
- Создать mapper из XData/ProjectData в RoomInput и ProjectSettings.
- Сделать строгую валидацию входных данных и единиц.
- Привести единый EquipmentCatalog к паспортным данным; убрать смешение Flamex и Proffex.
- При нехватке паспортной массы/остатка/гидравлических данных вернуть BLOCKED/WARNING, а не подставлять расчётный default.
- Реализовать выбор инженером набора модулей для каждого помещения, без молчаливого SuggestVol=120.
- Расширить тесты: семь золотых комнат, граничные значения, неправильные единицы, неверный K3, missing Mб, missing PResidualAbsMpa, недостаточная суммарная заправка, module choice.
- Сборка AGPT.dll должна доказуемо ссылаться на новую библиотеку; отдельный тест GasCalc не заменяет интеграционную сборку.

**Критерий выхода M1:** единственный расчётный путь в DLL + C# golden/unit tests + plugin build + evidence exact SHA. AutoCAD smoke-test ещё отдельный gate.

### M2 — альбом и оформление

- Одна ProjectData модель для титула, общих данных, таблиц, расчётных листов, спецификации и кабельного журнала.
- Удалить demo fallback при обычной команде; отдельный DEMO mode должен быть явно включён и маркирован.
- Общие данные и спецификация строятся только по результатам расчёта и выбранным инженером позициям.
- Таблицы — ACAD_TABLE; валидация листов и форматов по эталону МГИМО.
- Сверка геометрии/стилей/слоёв и наложений отдельным P8 regression report.

### M3 — трансформаторная зона, геометрия и АГПТ

- Из PDF/DWG создать таблицу исходных данных с точной привязкой к листу/координате/ревизии.
- Выделить защищаемые объёмы и проанализировать сценарии раздельных/совмещённых зон.
- Подключить реальные семейства модулей и насадков из паспортов.
- Автоматическая компоновка возможна только как предложение инженеру; насадки/трассы пересчитываются из общей модели.
- Гидравлика подключается только по методике изготовителя.

### M4 — автоматика и кабельная часть

- Устройства пожарной автоматики и линии ввода/вывода; точные модели и сертификаты.
- Проверка взаимодействия сигнализации, пусковых цепей, блокировок и ручного режима.
- Кабельные маршруты и КЖ формируются из фактической модели; никакой недоказанной марки кабеля по умолчанию.

### M5 — интеграция и выпуск

- Единый source of truth: помещения → модули → насадки → участки труб → гидравлика → устройства → кабели → листы/спецификация.
- Перекрёстная проверка расчётов и схем вторым оператором.
- Автосверка с эталоном, открытие/сохранение в AutoCAD 2026, проверка автозагрузки/NETLOAD и повторного запуска команд.
- Перед выпуском — список блокирующих предупреждений, подпись ответственного инженера и артефакты evidence.
