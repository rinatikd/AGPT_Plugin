# AGPT_Plugin — задание для ИИ-агентов: заполнение чертежей по эталону

Репозиторий: https://github.com/rinatikd/AGPT_Plugin (AutoCAD 2026 .NET плагин, альбом газового/порошкового пожаротушения).
Владелец: rinatikd. Рабочая ОС владельца: Windows, PowerShell, AutoCAD запущен локально. Язык общения и документации: русский.
Канал связи между агентами и владельцем: `bridge/INBOX.md` по `bridge/PROTOCOL.md` (см. раздел 9).

---

## 1. Цель

Плагин должен выпускать листы альбома АГПТ, которые **качественно и количественно повторяют эталон** (проект МГИМО, 5 DXF в корне репозитория): состав листов, таблицы, надписи, стили, слои, размеры. В части оформления и генерации файлов плагин должен быть не хуже эталона.

## 2. Жёсткие ограничения

1. **Рамку и штамп не трогать и не перерисовывать.** За них отвечает отдельный блок (рамка + штамп). Задача — только заполнение листов внутри рамки: таблицы, тексты, схемы, планы, выноски. Если код рисует рамку «запасным вариантом», сохранить текущее поведение, не «улучшать» его. Это отменяет прежний приоритет «Frame offset первым» из bridge/INBOX.md (13:42): компоновка контента должна обходить штамп, а не менять рамку.
2. Не выдумывать значения. Любые размеры, высоты текста, шрифты, имена слоёв берутся из эталона (раздел 4 и файлы `reference_spec/`, `sheets_dump/`). Если значения нет — написать вопрос владельцу в INBOX, а не подставлять «похожее».
3. Работать в отдельной ветке (`feature/<пакет>`), в `main` не пушить (исключение — файлы `bridge/`: сообщения и обмен файлами). Один пакет работ = одна ветка = один PR.
4. Агент **не может проверить результат в AutoCAD**. Сборка — `dotnet build` (README/BUILD.md; `build.bat` по HANDOVER.md сломан). Проверку в AutoCAD выполняет владелец; агент оформляет шаги проверки в PR и в INBOX.
5. Расчёты (масса ГОТВ, гидравлика) — инженерные. Формулы не менять без ссылки на СП 485 и без подтверждения владельцем.
6. Не коммитить данные заказчика, которых нет в репозитории. Не вшивать в код фамилии, шифры, названия организаций (см. раздел 5).

## 4. Что известно об эталоне (измерено по DXF)

### 4.1 Общее
- Единицы мм. Листы лежат в модели как вставки блоков рамки с масштабом: планы **1:40** (A3 альбомный) и **1:48** (A3 книжный, 297×420), общие листы тоже A3 1:40, задания в смежные разделы — **A4 книжный** (210×297, блок `*U87`).
- Блоки рамки: анонимные `*U…`, `РамкаА3`, `Ramka` (атрибуты штампа: `ЛИСТ_второй`, `ШИФР_ПРОЕКТА_ЛИСТ2`, стили `Архитектурный` и `СПДС`, высота текста штампа **2,5 мм бумаги**). Заполнение штампа — атрибутами блока, не линиями.
- Всего в эталоне 36 листов: файл «вторая» — 18, «первая А» — 5, «четвёртая» — 7, «третья» — 3 (листы A0 1189×841 с топографией/горизонталями — фон, не генерируется плагином), «пятая А» — 3.

### 4.2 Текстовые стили эталона
| Стиль | Шрифт | Коэф. ширины | Где |
|---|---|---|---|
| `GOST-2.304_Type-B_italic` | `GOST_Common Italic.ttf` | 1,0 | основной стиль листов АГПТ, номера листов, общие тексты |
| `СПДС` | `isocpeur.ttf` | 0,9 | штамп, таблицы |
| `Архитектурный` | `isocpeui.ttf` | 1,0 | штамп, номера выносок на схемах (2,5 мм) |
| `RubezhCAD` | `arial.ttf` | 0,8 | |
| `Проект` (текст MTEXT листов «Общие данные») | см. `reference_spec` | | заголовки и общие указания |
| ARIAL / STANDARD | arial | подгонка ~0,71 | подписи «Согласовано», фамилии |

Высоты на бумаге (мм): штамп 2,5; основной текст MTEXT 3,5–3,75; нумерация листа 2,81; текст в таблицах 2,1–2,5; подписи «Согласовано» 2,53. На модели = бумага × масштаб листа (для 1:40 — 100, 112,5, 150).
Перед применением сверить с `reference_spec/*.json` → `styles`, `text_styles_used`.

### 4.3 Слои эталона (имя, цвет, вес)
`АГПТ` (7, по умолчанию) — основной слой всех элементов АГПТ; `АСПТ`; `О_Формат`, `Формат` (вес 20) — рамки; `4.4.4._Сэндвич` (252, вес 53) — подписи «Общие данные (начало/продолжение)»; `013` (вес 18); `RC-Таблицы` — таблица спецификации. Слои подосновы архитектуры (`®_КИРПИЧ_120`, `®_ЛЕСТНИЦА`, `Стена`, `Оси`) создаёт чужой чертёж, плагин их не создаёт.

## 5. Расхождения текущего кода с эталоном (из ревью `AGPT_Plugin_Drawings.cs`)

1. **Код написан по образцу «Детский сад АГПТ» (12 листов)**, а не по МГИМО: нет листов T3 «Общие данные (продолжение)», T4/T5 в виде эталонных расчётных листов, T1 как отдельного A4. Состав листов в `FullAlbum` (≈ строка 1833) надо привести к каталогу 4.4.
2. **Таблицы рисуются линиями**, а в эталоне это `ACAD_TABLE` с точными размерами колонок/строк (4.4).
3. **Контент накладывается на штамп.** Глобальный `ContentBottom` (=90) не решает проблему; жёстко заданные координаты ниже «пола» (y=96) остались: структурная схема (`o.Y+42`, `+32`, рамка клемм `o.Y+80`), титульные листы (`o.Y+28`, подписи от `o.Y+85`), аксонометрия (`o.Y+105`). Штамп занимает только правый нижний угол (≈185×55 + блок подписей 105×55 в запасной рамке; у внешнего блока размеры брать из блока).
4. **Баг `Draw.Table`:** если таблица уходит ниже пола, её поднимают вверх, и она налезает на содержимое выше (лист аксонометрии: 17 строк ≈58 мм). Автоподъём (bridge/INBOX.md, 13:40) убрать и заменить разбивкой/переносом.
5. **Блок рамки:** код ищет `blocks\ММХ_Штамп.dwg`; в репозитории папки `blocks/` нет, в эталоне такого блока нет (там `Ramka`/`РамкаА3`). Уточнить у владельца, какой именно блок рамки используется в проекте. Рамку не менять, но загрузка блока не должна молча падать в запасной вариант без сообщения.
6. **Зашитые данные:** фамилии, шифр, организация; `*_ALBUM` без зон тихо подставляет демо-данные детского сада.
7. **Гигиена репозитория:** README/HANDOVER ссылаются на несуществующие `blocks/`, `bundle/`, `install_bundle.bat`, `VERIFY.md`; в корне лежат чертежи заказчика (МГИМО, детсад) — вынести в `samples/` или в Git LFS, вопрос о публичности решает владелец.

## 6. Пакеты работ

Порядок — по зависимостям. Каждый пакет: ветка, PR, описание изменений, шаги проверки в AutoCAD для владельца, ссылка на конкретные листы эталона.

- **P0. Подготовка.** Закоммитить `sheets_dump/` (или сделать `tools/make_reference.ps1`, который его строит). Добавить `reference_catalog.json` (из раздела 4.4, машиночитаемый: типы листов, таблицы с шириной колонок/высотой строк, тексты, стили, слои). Исправить README/BUILD.md (одна рабочая инструкция сборки). *Приёмка:* свежий клон + 1 команда воспроизводит JSON-выгрузки.
- **P1. Стили и слои.** Создание текстовых стилей и слоёв плагина с точными значениями (4.2, 4.3) вместо констант «на глаз». Высоты на бумаге в одном месте (`DL`), модельная высота = бумага × масштаб листа. *Приёмка:* после `*_INIT` стили/слои в DWG совпадают с `reference_spec` (скрипт сверки).
- **P2. Таблицы.** Функция `Draw.AcadTable` на `Autodesk.AutoCAD.DatabaseServices.Table`: ширины колонок, высоты строк, стиль текста, высота, выравнивание, слияние ячеек заголовка — по каталогу. Структура — по схеме ChatGPT (INBOX 13:42, B): TableSpec → TableLayout → TableRenderer, вызовы SetColumnWidth/SetRowHeight только внутри адаптера. Корректная разбивка по листам вместо подъёма вверх. *Приёмка:* таблицы T2–T5 по размеру и тексту совпадают с эталоном.
- **P3. Листы T2/T3 «Общие данные».** Ведомость рабочих чертежей и ссылочных документов — из реального состава сгенерированного альбома, а не из константы. Блок «Согласовано» и общие указания — из `ProjectData`. *Приёмка:* два листа визуально и по таблицам совпадают с листами 4 и 5 файла «вторая».
- **P4. Расчётные листы T4/T5.** «Исходные данные», «Результаты расчетов», «ТРУБОПРОВОДНАЯ РАЗВОДКА», по листу на этаж/зону; формулы Mp, Mtr, Mг, K2 — как сейчас, значения форматируются как в эталоне (десятичная запятая в отдельных колонках, разрядность). Расчётная схема с узлами. *Приёмка:* на данных эталона (МГИМО, серверная 12,00 м² и т. д.) цифры совпадают с таблицами листов 6, 9–12.
- **P5. Спецификация T7.** Колонки и разделы по каталогу; позиции из расчёта. *Приёмка:* лист 1 файла «вторая». Профиль ГОСТ 21.110 фиксировать по нормативному тексту и эталону, не по внешнему сходству.
- **P6. Планы T8/T9.** Сначала выгрузка геометрии планов эталона (расширить `dump_sheets.py`: слои, типы линий, вставки блоков с координатами, MULTILEADER-стили, DIMSTYLE), потом реализация выносок, размеров, блоков. *Приёмка:* визуальная сверка с листами файлов «первая А», «четвёртая», «пятая А». Проверка `AGPT_ZONE`: незамкнутая полилиния отклоняется, единицы мм↔м преобразуются в одном месте, тесты на известной длине и площади.
- **P7. T1 «Задания в смежные разделы».** A4 книжный, MTEXT с форматированием (отступы, табуляция, нумерация).
- **P8. Автосверка.** Скрипт: сгенерировать альбом → сохранить DXF → прогнать `dump_sheets.py` → сравнить с `reference_catalog.json` (набор таблиц, размеры колонок, стили/высоты, слои, число выносок/размеров) → отчёт расхождений. Допуски: размеры ±0,1 мм бумаги, высоты текста точно.
- **P9. Гигиена.** Убрать зашитые данные в `ProjectData`, демо-режим только по явной команде, перенос чертежей заказчика, актуализация HANDOVER.

## 7. Правила для агента

## 9. Обмен сообщениями и файлами через репозиторий

- **Сообщения:** `bridge/INBOX.md`, формат и правила — `bridge/PROTOCOL.md` (участники: Grok, ChatGPT, Claude, Human). Новый блок — в конец файла, чужие блоки не менять. Тема работы по этому заданию: `TOPIC: ref-<пакет>` (например `ref-P2-tables`).
- **Файлы** (выгрузки, патчи, скриншоты проверки, отчёты сверки): `bridge/files/<YYYY-MM-DD>_<отправитель>_<имя>`; в сообщении INBOX дать относительный путь. Файлы больше ~1 МБ коннектор GitHub не читает: держать JSON/текст компактным, большие бинарники не класть.
- **Человек (владелец)** делает `git pull`, собирает, проверяет в AutoCAD и отвечает блоком `FROM: Human` с результатом (что открылось, что наложилось, скриншот в `bridge/files/`).
- Секреты и ключи в репозиторий не писать.
